# Repo Manager 1.2.29

Веб-менеджер локальных зеркал deb и rpm для закрытого контура. Ставится на Oracle Linux 10, отдаёт пакеты через nginx и умеет публиковать свои пакеты.

Интерфейс открывается по `http://IP/` (порт 80, nginx). Само приложение слушает только `127.0.0.1:8000` и с других машин не открывается. Страницу и `/api/` пускает только список в `/var/lib/repo-manager/api-allow.conf` (по умолчанию этот сервер и сеть `192.168.3.0/24`). Каталоги `/repo/` и `/cache/` открыты для клиентов.

## Что умеет

- Зеркала RPM через `dnf reposync` и DEB через `aptly`.
- Свои локальные репозитории: rpm, deb и простой каталог файлов.
- Кэш по запросу: пакет скачивается, когда клиент первый раз его просит.
- Расписание sync в cron, повтор через час после ошибки, очередь и лимит одновременных sync.
- Стоп синхронизации, порог свободного места, прокси для исходящих загрузок.
- Очистка кэша по расписанию.
- Импорт и экспорт списка зеркал.
- Логи sync в `/var/lib/repo-manager/logs`. В интерфейсе только история: название, время и результат.
- Проверка, что nginx отдаёт `repomd.xml` или `Release`.

Авторизации в интерфейсе нет. Подпись репозиториев и уведомления не включены.

## Требования

- Oracle Linux 10, x86_64.
- PostgreSQL, nginx, Python 3.12.
- Для RPM: `dnf-plugins-core`, `createrepo_c`.
- Для DEB: бинарник `aptly` из архива установки.
- Отдельный диск под `/var/lib/repo-manager`. Полный Debian или Ubuntu занимает сотни гигабайт.

## Установка без интернета

На машине с интернетом один раз собирается архив (`scripts/build-offline.sh`). На сервере:

```bash
tar xzf RM-offline.tar.gz
cd repo-manager
sudo bash scripts/install-offline.sh
```

Скрипт ставит пакеты из репозитория OL, создаёт пользователя `repoman`, базу `repo_manager`, venv и службу `repo-manager`. Пароль базы печатается в конце. В `pg_hba.conf` для localhost нужен `scram-sha-256`, не `ident`.

```bash
systemctl status repo-manager
curl -s http://127.0.0.1:8000/health
```

Веб-интерфейс: `http://IP/`. Клиентские репозитории: `http://IP/repo/...`.

## Каталоги

| Путь | Назначение |
|---|---|
| `/opt/repo-manager` | код и venv |
| `/var/lib/repo-manager/mirrors` | зеркала RPM и исходные файлы DEB |
| `/var/lib/repo-manager/public` | публикация aptly, её отдаёт nginx |
| `/var/lib/repo-manager/local` | свои пакеты и файлы |
| `/var/lib/repo-manager/cache` | кэш по запросу |
| `/var/lib/repo-manager/logs` | файлы sync |
| `/var/lib/repo-manager/proxy.json` | прокси, порог диска, лимит sync, очистка кэша |

## Как завести зеркало

RPM. URL должен открывать каталог с `repodata/repomd.xml`.

```text
http://mirror.yandex.ru/oracle/OL10/baseos/latest/x86_64/
```

DEB. URL — корень архива, distribution — имя из `dists`.

```text
URL: http://mirror.yandex.ru/debian/
distribution: bookworm
components: main
architectures: amd64
```

Для `trixie-security` компонент в aptly — `updates/main`, не `main`. Security Ubuntu лежит на том же зеркале, что и релиз: `jammy-security`.

Импорт — текстовый файл, кнопка «Импорт». Поля через `|`: имя, тип, URL, distribution, components, architectures, cron.

```text
OL10_BaseOS|rpm|http://mirror.yandex.ru/oracle/OL10/baseos/latest/x86_64/||||x86_64|0 3 * * *
Ubuntu22_jammy|deb|http://mirror.yandex.ru/ubuntu/|jammy|main,restricted,universe|amd64|0 2 * * *
```

Импорт создаёт запись. Для deb ещё создаёт зеркало aptly. Пакеты качаются только после Sync.

Строка клиента:

```text
baseurl=http://IP/repo/rpm/OL10_BaseOS
deb http://IP/repo/deb/Ubuntu22_jammy jammy main
```

## Меню

- Задачи — история синхронизаций и очистки aptly. Это не расписание.
- Настройки → Прокси — исходящий `http://user:pass@proxy:3128` и исключения.
- Настройки → Место — минимум свободных ГБ, лимит одновременных sync и повтор после ошибки. Пустое поле порога снимает ограничение. Ниже порога sync не стартует.
- Настройки → Очистка кэша — cron и срок в днях. Пример: `0 4 * * *` и `14`.
- Настройки → Обновление — архив `RM-*-offline.tar.gz` новее текущей версии.
- Убрать каталоги без зеркал — публикации aptly, которых уже нет в базе. Зеркала из списка не трогает.
- Почистить пул — пакеты aptly, на которые никто не ссылается.

Полоска диска в шапке: до 70% зелёная, до 90% жёлтая, от 91% красная. Cron зеркала — пять полей, например `0 3 * * *` (каждый день в 03:00). Для проверки каждую минуту: `* * * * *`.

## Обновление

Из браузера: меню → Настройки → Обновление. Служба останавливается на минуту и поднимается сама. Зеркала, база и `.env` не трогаются. Если идёт sync, обновление не стартует.

С сервера, от root:

```bash
bash /opt/repo-manager/scripts/repo-manager-update.sh apply /root/RM-1.2.29-offline.tar.gz
tail -f /var/lib/repo-manager/logs/update.log
```

Откат последней замены кода: кнопка «Откатить» или `repo-manager-update.sh rollback`. Рестарт службы обрывает текущий sync.

## История

### 1.2.29

- Перед sync Debian считается размер по индексу Packages. На карточке видно, сколько пакетов и гигабайт займёт зеркало.
- Если свободного места меньше, чем ещё предстоит скачать, плюс 1 ГБ, sync не стартует. Уже скачанное вычитается. Если индекс не открылся, sync не блокируется.
- Во время sync Debian на карточке две цифры: размер этого репозитория и общий пул aptly.
- После удаления Debian с файлами напоминание: пул сам не уменьшится, место освобождает «Почистить пул».

### 1.2.28

- Debian-зеркало с тем же именем, адресом и дистрибутивом снова создаётся, если aptly его ещё помнит. Чужой адрес не подхватывается.
- Строки «идёт» в истории закрываются, когда процесса уже нет. Новый sync для этого не нужен.
- Во время sync карточка показывает число пакетов с диска, а не держит 0, пока обход каталога не устареет.

### 1.2.27

- Пока идёт sync, удалить нельзя.

### 1.2.8.0

- Очистка пула, снятие каталогов без зеркал и удаление файлов DEB идут в фоне.
- Пока идёт закачка, свободное место проверяется каждые 10 секунд. Ниже порога sync останавливается.
- У качающегося Debian на карточке число пакетов из вывода aptly и размер своего каталога, а не ноль до публикации.
- На странице зеркала у RPM скрыты Distribution и Components, у DEB скрыт Repoid.

### 1.2.7.9

- Если база aptly повреждена (`leveldb: manifest corrupted`), перед очисткой выполняется `aptly db recover`.

### 1.2.7.8

- aptly ставится в `/usr/local/bin` и ссылкой в `/usr/bin`. Приложение вызывает полный путь.

### 1.2.7.7

- «Убрать каталоги без зеркал» удаляет каталоги в `public/` и зеркала aptly, которых уже нет в базе.
- Удаление DEB снимает публикацию по фактическому distribution.

### 1.2.7.6

- Массовое удаление не пропускает зеркало только из-за статуса «идёт». Отказ остаётся, пока процесс sync реально жив.
- Если в ошибке есть текст, он показывается. Для DEB с файлами снимается и каталог публикации.

### 1.2.7.5

- Лимит одновременных sync учитывает уже запущенные задачи. «Sync все» и одинаковый cron не обходят лимит.
- Сохранение настроек DEB меняет зеркало aptly: URL и архитектуру на месте, дистрибутив и компоненты — пересозданием зеркала.
- На пустом списке остаётся подпись «список пуст».

### 1.2.7.4

- Планировщик запускает sync по cron.
- У нового DEB-зеркала архитектура по умолчанию `amd64`, у RPM — `x86_64`.
- Размер Debian считается по каталогу `public/Имя`, а не по общему пулу aptly.
- История на странице зеркала — 50 записей. После sync лампочка снова проверяет nginx.
- Фильтр «Идёт» показывает и очередь. Версия в меню берётся из файла `VERSION`.

### 1.2.6

- Подсчёт места больше не создаёт лишнюю нагрузку на диск во время sync.

### 1.2.5

- Подсчёт размера не блокирует интерфейс во время sync.
- Планировщик использует ту же очередь, что и «Sync все», и не запускает лишнее сверх лимита.
- Нельзя удалить зеркало, пока оно в очереди.

### 1.2.4

- RPM sync отключает системные репозитории и не использует fastestmirror.
- В лог зеркала пишется короткая причина, без traceback на весь экран.

### 1.2.3

- «Sync все» не отбрасывает лишние зеркала. По лимиту стартуют первые, остальные встают в очередь.
- На карточке статус «в очереди». Стоп снимает зеркало с очереди.
- После перезапуска службы очередь восстанавливается.
